# LOOM 产品定义

LOOM 面向希望在自己电脑上组合 AI 与工具的用户，以及需要为宿主开发独立能力的插件作者。它解决的问题不是再做一个固定功能聊天框，而是让插件安装、配置、授权和执行都可以检查，让模型只能看到目前已启用的工具。

## 产品形态与 MVP

CLI 用于可重复操作和插件开发；本地 Web 控制台用于查看插件状态、编辑配置、运行工具与检查 Agent 的执行事件。两者复用同一宿主核心和本地数据。默认不安装任何插件，用户从本机示例目录或自己的分发目录进行安装。

P0 是完整的插件生命周期、动态工具注册与执行、真实模型接口、可检查的结果，以及工作区检索和本地笔记两个独立插件。成功标准是：新目录插件能够在不修改宿主源码的情况下被发现、安装、启用并运行；禁用后工具消失；修改配置后授权失效；笔记能跨进程重启保存。

P1 包括 Schema 表单、高级 JSON、取消、写入确认、历史摘要与模型连接检查。本次不做在线插件市场、远程安装、自动升级、多用户登录、OS 级沙箱、桌面安装包或后台系统自启动。

## 核心用户路径

在“插件”页选择本地示例或填写分发目录，预检清单与摘要。用户确认已经审查并信任代码后安装，此时插件仍然禁用。用户编辑配置、确认能力范围，再启用插件。在“运行台”选择动态工具并填入参数，不需要模型即可直接运行；需要模型组合工具时，提交 Agent 任务并检查事件与结果。写入工具在 Agent 中逐次请求批准。

工作区检索返回真正从限定目录读到的路径、行号与内容。笔记插件使用按插件隔离的本地存储，保存用户确认的内容。二者不是两个外观不同的聊天提示，而是具有不同权限、输入、数据来源和持久化行为的独立模块。

## 交互判断

控制台采用工业编辑工作台：固定导航、温白工作面、克制的蓝紫操作色、等宽工具名和细线分区。把“本地”“已安装”“已启用”和“需要授权”分开表达，避免用一个绿色状态掩盖权限或模型不可用。

安装和启用各自解释不同边界；配置保存后明确告知需要重新授权。加载操作禁止重复提交；零安装和零工具状态引导下一步。失败显示真实错误与恢复方法，不伪造进度或结果。运行可取消，取消已经开始的写入不等于回滚，需检查插件存储。卸载和清空历史均需要确认。

模型设置默认是回环 Ollama。未安装模型不会妨碍直接运行插件。切换远程接口前明确说明提示词、工具参数与工具结果可能外发；密钥只放宿主环境，不在浏览器输入或保存。
