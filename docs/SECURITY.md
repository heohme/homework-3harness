# 安全与隐私边界

## 只运行可信插件

本项目不是执行任意不可信代码的安全沙箱。插件运行在本机用户权限下的 Node 子进程中；代码可以绕过 ctx 自己导入 fs、访问网络或调用其他 OS 能力。只有已经审查并信任作者和代码的插件才能安装。界面的信任确认表示用户接受运行代码的风险，不代表宿主证明其安全。

进程分离、清理环境、超时、堆大小、输出限制、安装摘要和权限代理用于可观察性与减少意外影响。它们不提供 OS 级隔离，也不保证恶意插件的资源或网络行为受控。Node 的权限模型同样不能作为恶意代码安全保证，参见 SOURCES.md。

## 能力与授权

插件清单声明 workspace.read、storage.read、storage.write。安装后禁用；启用需要逐项覆盖全部声明权限。工作区实际范围是 config.root，路径规范化且 broker 拒绝跳出根目录、符号链接、隐藏文件、密钥后缀、依赖和构建目录，仅支持已知文本类型。文件列表最多 100 项、遍历深度 12、文件内容最多 64 KiB。

配置改变清除授权，禁用插件移除动态工具。只读工具即使插件拥有 storage.write 也不能调用 broker 写入。Agent 使用写工具时逐次批准，拒绝不触发插件。手动工具命令是用户直接操作，Web 对写工具提供确认。批准不是回滚机制：如果操作已开始后取消，写入可能已经完成。

## 本地数据

应用没有遥测，不默认联网同步，没有账号体系。应用私有数据在 .harness/ 或明确配置的 HARNESS_HOME；本机文件权限防止一般其他用户读取，但不能防同用户恶意程序。配置和笔记均不加密，应依赖系统磁盘加密及自己的备份策略。

提示词、工具参数、工具结果和详细事件只留在当前宿主内存，最多 50 个运行记录。磁盘历史仅存 id、类型、状态、工具名与时间摘要；重启后不能恢复详细执行内容。笔记插件的作用就是持久化笔记，所以用户确认的笔记正文会存于 storage/local-notes.json。工作区文件只读取，不复制到应用数据库。

卸载删除该插件的快照、配置和插件存储；清空历史删除运行摘要和当前内存记录。删除整个 .harness/ 会丢失所有本地配置与插件数据，应先停止宿主并备份；仓库源码不受影响。系统备份或文件系统快照可能仍保留删除过的数据，本项目不提供安全擦除。

## 模型与外发

默认回环 Ollama，不自动安装模型。模型可以接收用户提示、启用工具定义和被调用工具的结果。本机模型仍可能保存自身日志，需另行查看模型服务配置。

远程兼容接口必须手动允许 allowRemote 并使用 HTTPS。开启后，任务提示、工具参数、笔记或工作区工具结果可能发送给该提供商；这时不再是数据完全不出机。HARNESS_MODEL_API_KEY 只从宿主环境读取，不下发浏览器、不写注册表，也不传给插件进程。不要把凭据放在插件配置或提示词中。第三方插件本身是否联网取决于受信任的实现，本宿主不能阻止恶意插件外发。

## Web 与异常

Web 只监听 127.0.0.1，严格校验 Host / Origin，会话令牌仅保留于内存，无 CORS，拒绝跨站访问与嵌入。不能通过绑定 0.0.0.0 对局域网共享。会话失效时刷新即可；不提供公网或多用户认证。

端口占用不自动换端口，用户应停止旧进程或明确指定 --port。非法清单、输入与配置返回错误；文件摘要变化拒绝执行；插件崩溃、超时或输出过量终止进程；模型不可用报告失败，可改为直接运行插件。损坏的 JSON 不会自动覆盖，应停止应用、备份并手动恢复。
